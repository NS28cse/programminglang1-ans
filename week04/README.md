## 課題1　料金を分類する（`Fee` / `fee.c`）

**要点**: `else if` は上から調べて**最初に真になった 1 つ**だけを実行する。不正な値を最初に除き，小さい区分から `<=` で調べると，各条件は「上限」だけで書ける。
境界（5 と 6，17 と 18，−1 と 0）の両側を試す。

**解答**: [Fee/fee.c](Fee/fee.c)

```c
    int age = 17;   // 入力の代わりの固定値（-1, 0, 5, 6, 17, 18 に変えて確かめる）

    if (age < 0) {
        printf("invalid\n");
    } else if (age <= 5) {      // 0〜5 歳
        printf("0\n");
    } else if (age <= 17) {     // 6〜17 歳（5 以下はここまでに除かれている）
        printf("500\n");
    } else {                    // 残りは 18 歳以上だけ
        printf("1000\n");
    }
```

**実行結果**（`age = 17`）

```text
500
```

**演習ページの表**（各値に変えてビルド・実行した結果。テスト `Fee/age_17`・`age_m1`・`age_0`・`age_5`・`age_6`・`age_18`）

| `age` | 期待する表示 | 調べる境界 | 真になった条件（それより上の条件はすべて偽） |
| ---: | --- | --- | --- |
| −1 | `invalid` | 許される範囲の手前 | `age < 0` |
| 0 | `0` | 最小の有効値 | `age <= 5` |
| 5 | `0` | 無料の最後 | `age <= 5` |
| 6 | `500` | 500の最初 | `age <= 17` |
| 17 | `500` | 500の最後 | `age <= 17` |
| 18 | `1000` | 1000の最初 | どれも偽 → `else` |

どの値でも，表示は 1 行（数値または `invalid` と改行）だけになる。`printf` は 4 つのうち必ずちょうど 1 つが実行される。

### 条件の順序を確かめる

`age <= 17` を `age <= 5` より前に置いた版（確認後は元に戻す）:

```c
    if (age < 0) {
        printf("invalid\n");
    } else if (age <= 17) {
        printf("500\n");
    } else if (age <= 5) {
        printf("0\n");
    } else {
        printf("1000\n");
    }
```

| 変更した値 | 予想 | 実行結果 | そうなる理由 |
| --- | --- | --- | --- |
| `age = 5`（順序を入れ替えた版） | `500` | `500` | `age < 0` は偽，次の `age <= 17` が真なのでここで決まる。`age <= 5` は調べられない |
| `age = 0`（同） | `500` | `500` | 同上。0〜5 歳も 500 になる（無料の区分が使われなくなる） |
| `age = 6`, `17`, `18`, `−1`（同） | `500`, `500`, `1000`, `invalid` | `500`, `500`, `1000`, `invalid` | 6〜17・18 以上・負の値は元の版と同じ |

入れ替えた版では，`age <= 5` が真になる値（0〜5）はその前の `age <= 17` でも必ず真になるので，`age <= 5` の本体は**どの値でも実行されない**。
警告は出ない（GCC・Clang・MSVC とも）ので，境界の値を実際に試さないと気付けない。講義の「90点以上を先に調べる」と同じで，**範囲の狭い（上限の小さい）条件を先に**調べる。

### `else if` を別々の `if` にすると

`else if` の `else` を外して，次の 3 つの独立した `if` にした版:

```c
    if (age < 0) {
        printf("invalid\n");
    }
    if (age <= 5) {
        printf("0\n");
    }
    if (age <= 17) {
        printf("500\n");
    } else {
        printf("1000\n");
    }
```

| `age` | −1 | 0 | 5 | 6 | 17 | 18 |
| --- | --- | --- | --- | --- | --- | --- |
| 表示（実行結果） | `invalid`<br>`0`<br>`500` | `0`<br>`500` | `0`<br>`500` | `500` | `500` | `1000` |

**説明（条件が独立になること）**:

```text
else if の連鎖（どれか 1 つ）            別々の if（それぞれ独立）
  age < 0 ?  ─真→ invalid ─┐             age < 0 ?   ─真→ invalid
     │偽                    │                  ↓（真でも偽でも次へ）
  age <= 5 ? ─真→ 0 ───────┤             age <= 5 ?  ─真→ 0
     │偽                    │                  ↓
  age <= 17 ?─真→ 500 ─────┤             age <= 17 ? ─真→ 500
     │偽                    │                  │偽→ 1000
    1000 ──────────────────┴→ 次の文            ↓
                                              次の文
```

`else if` では，前の条件が**偽だったときだけ**次の条件を調べ，真になった時点で残りを飛ばして分岐の後へ進む。
別々の `if` では，前の条件の結果に関係なく**すべての条件を毎回調べる**。−1 は `age < 0`・`age <= 5`・`age <= 17` のすべてを満たすので 3 行表示され，0〜5 は 2 つを満たすので 2 行表示される。
最後の `else` は直前の `if (age <= 17)` だけに対応するので，18 以上でだけ `1000` になる。

### 説明すること

**負の年齢の検査を省くと，−1 はどの区分に入るか。**
→ **0（無料）の区分**に入り，`0` と表示される（実行して確認）。−1 ≦ 5 なので最初の `age <= 5` が真になるから。
`age <= 5` という条件は「0 以上」を含んでいない。下限を書かなくてよいのは，その前で `age < 0` を除いてあるからで，検査を省くとその前提が崩れる。

**18 歳以上を最後の `else` だけで表せるのはなぜか。**
→ `else` に来るのは，`age < 0`・`age <= 5`・`age <= 17` が**すべて偽**だった値，つまり `age >= 0` かつ `age > 17` の値で，`int` では `age >= 18` と同じだから。
`else if (age >= 18)` と書いても結果は同じだが，条件は常に真なので不要。最後を `else` にすると，「どれか 1 行だけ」に必ず該当し，どの区分にも入らない値がなくなる。

**どの条件が真になり，何回本体を実行したか**: 上の表の右端の列のとおり。分岐なので，選ばれた本体を 1 回だけ実行する（ループではない）。

**採点のポイント・よくある誤り**

- 6 つの値すべてを試した記録があるか。特に 5 と 6，17 と 18 の両側。17 だけ試して正しいと判断していないか。
- `age < 17` と書く誤り（17 で `1000` になる）や `age < 5`（5 で `500` になる）。`<` を使うなら `age < 6`・`age < 18` が正しい。
- 負の検査を最後や途中に置く誤り。例えば `if (age <= 5)` を先に書くと −1 が `0` になる（上の「説明すること」）。
- 表示は数値と改行だけ。`fee=500`・`500 yen` のような余分な文字や，改行の書き忘れは指定違反。
- `if (age = 0)` のような代入の誤り（MSVC `/W4` は C4706「条件式の中で代入が行われました」，GCC は `-Wparentheses` で警告）。警告を読んで直したかを見る。
- `age >= 0 && age <= 5` のように下限も書くのは誤りではない（冗長なだけ）。`else if` を別々の `if` にした提出は，−1 や 0〜5 で複数行表示されるので不可。

## 課題2　偶数の合計（`EvenSum` / `even_sum.c`）

**要点**: 累積用の `sum`（それまでの結果）とカウンタ `i`（今調べている数）の役割の違い。`sum` はループの**前**で 1 回だけ初期化する。
`for` の実行順「初期化 → 条件判定 → 本体 → 更新 → 条件判定…」と，同じ処理の `while` 版への書き換え。

**解答**: [EvenSum/even_sum.c](EvenSum/even_sum.c)

```c
    int n = 10;     // 入力の代わりの固定値（0, 1, 2, 4, 100 に変えて確かめる）
    int sum = 0;    // それまでの合計．ループの前で 1 回だけ 0 にする

    for (int i = 1; i <= n; ++i) {      // i は今調べている数
        if (i % 2 == 0) {               // 偶数のときだけ加算する
            sum += i;
        }
    }
    printf("%d\n", sum);
```

**実行結果**（`n = 10`）

```text
30
```

**`n` を変えた結果**（3 つの版とも同じ表示。テスト `EvenSum/n_10`・`for_n_*`・`while_n_*`・`step2_n_*`）

| `n` | 表示（実行結果） | 加算した値 |
| ---: | ---: | --- |
| 0 | 0 | なし（本体 0 回） |
| 1 | 0 | なし（1 は奇数） |
| 2 | 2 | 2 |
| 4 | 6 | 2 + 4 |
| 10 | 30 | 2 + 4 + 6 + 8 + 10 |
| 100 | 2550 | 2 + 4 + … + 100（50 個。2 × (1 + 2 + … + 50) = 2 × 1275） |

### 値を追跡する（`n = 4`）

| 本体に入るときの`i` | 偶数か | 加算前の`sum` | 加算後の`sum` |
| ---: | --- | ---: | ---: |
| 1 | いいえ | 0 | 0 |
| 2 | はい | 0 | **2** |
| 3 | いいえ | **2** | **2** |
| 4 | はい | **2** | **6** |

更新で `i` が 5 になると `5 <= 4` が偽になって抜ける。表示は `6`（`n = 4` に変えて実行して確認。テスト `EvenSum/for_n_4`）。
条件判定は 5 回（`i` = 1, 2, 3, 4, 5），本体は 4 回，加算は 2 回。

### `while` へ書き換える

[EvenSum/versions/even_sum_while.c](EvenSum/versions/even_sum_while.c)（`for` 全体を次で置き換える。`sum` の初期化と最後の `printf` はそのまま）

```c
    int i = 1;                  // for の初期化
    while (i <= n) {            // for の継続条件
        if (i % 2 == 0) {
            sum += i;
        }
        ++i;                    // for の更新（本体の最後）
    }
```

`n` = 0, 1, 2, 10, 100 で，表示は `for` 版と同じ `0`・`0`・`2`・`30`・`2550` になった（上の表。テスト `EvenSum/while_n_*`）。
`i` の有効範囲だけが違う: `for` の初期化で宣言した `i` は `for` の外で使えないが，`while` 版の `i` はループの後でも使える（値は `n + 1`）。

### 説明すること

**`n = 0` では条件判定と本体はそれぞれ何回行われるか。**
→ **条件判定 1 回，本体 0 回**（数える変数を足して確認）。初期化で `i = 1` とした後，最初の条件判定 `1 <= 0` が偽なので，本体も更新も行わずに抜ける。
`sum` は 0 のままで `0` を表示する。`while` 版でも同じ（`while` は条件を先に調べる）。

**`sum = 0` を本体の中へ移してはいけないのはなぜか。**
→ 本体を実行するたびに `sum` が 0 に戻り，それまでに加えた合計が消えて**累積にならない**から。最後の反復で加えた分しか残らない。
例えば本体の先頭に `sum = 0;` を置くと，`n = 10` では `10`，`n = 4` では `4`，`n = 9` では `0` と表示された（実行して確認）。
また `int sum = 0;` という宣言ごと本体（ブロック）の中へ移すと，`sum` はそのブロックの中でしか使えないので，ループの後の `printf` で使えずコンパイルエラーになる
（MSVC: C2065「定義されていない識別子です」，GCC: `'sum' undeclared`）。

### 余裕があれば: `i` を 2 から始めて 2 ずつ増やす

[EvenSum/versions/even_sum_step2.c](EvenSum/versions/even_sum_step2.c)

```c
    for (int i = 2; i <= n; i += 2) {
        sum += i;
    }
```

`i` は偶数だけを通るので偶奇判定の `if` は不要。出力は同じ（テスト `EvenSum/step2_n_*`）だが，本体の実行回数が約半分になる（数える変数を足して確認）。

| `n` | 表示 | `for`＋`if` 版: 条件判定 / 本体 / 加算 | 2 ずつ版: 条件判定 / 本体 |
| ---: | ---: | --- | --- |
| 0 | 0 | 1 / 0 / 0 | 1 / 0 |
| 1 | 0 | 2 / 1 / 0 | 1 / 0 |
| 2 | 2 | 3 / 2 / 1 | 2 / 1 |
| 4 | 6 | 5 / 4 / 2 | 3 / 2 |
| 10 | 30 | 11 / 10 / 5 | 6 / 5 |
| 100 | 2550 | 101 / 100 / 50 | 51 / 50 |

`n` = 0, 1 は本体 0 回，`n` = 2 は 1 回，それより大きいと複数回になる（2 ずつ版）。0 回・1 回・複数回のどれも同じ式で正しい結果になることを確かめる。

**採点のポイント・よくある誤り**

- 0, 1, 2, 10, 100 のすべてで確認したか（期待値 0, 0, 2, 30, 2550）。`n = 4` の追跡表が埋まっていて，実行結果 `6` と一致しているか。
- 条件 `i < n` の誤り: `n` が偶数のとき最後の `n` を加えない（`n = 10` で `20`，`n = 2` で `0`）。
- `sum` の初期化をループの中に置く／初期化を忘れる（初期化していない変数の値を使うのは誤り。MSVC は C4700 の警告）。
- `i % 2 == 1` を偶数の判定にしている，`i / 2 == 0` と書いている，など判定式の誤り。
- `while` 版で更新 `++i` を忘れる（終わらない），`while (i <= n);` とセミコロンを付ける（本体が空の反復で終わらない）。
- `while` 版で `++i` を本体の**先頭**に置く誤り: `i` = 2〜`n + 1` を調べることになり，`n = 10` では偶然 `30` と正しく見えるが，
  `n = 1` で `2`，`n = 9` で `30`（正しくは `0`，`20`）になる（実行して確認）。`n = 10` だけでなく境界の値で確かめたかを見る。
- 「本体の実行回数が違う」を，回数（10 回と 5 回など）で具体的に書いているか。

## 課題3　小さな掛け算表（`Table` / `table.c`）

**要点**: 二重ループでは，外側が 1 回進むたびに内側が初期化から最後まで動く。値の表示は内側，行末の改行は内側のループが**終わった後**（外側の本体の最後）に置く。
列の区切りは「最後の列以外」にだけ出し，行末に余分な空白を付けない。

**解答**: [Table/table.c](Table/table.c)

```c
    for (int row = 1; row <= 3; ++row) {
        for (int col = 1; col <= 3; ++col) {   // 行が変わるたびに col は 1 から始まる
            printf("%2d", row * col);
            if (col < 3) {                      // 列の間だけ区切りを入れ，行末には付けない
                printf(" ");
            }
        }
        printf("\n");                           // 内側のループが終わった後に 1 回だけ改行する
    }
```

**実行結果**（行末に空白はない。テスト `Table/basic`）

```text
 1  2  3
 2  4  6
 3  6  9
```

`%2d` は最低 2 文字幅なので 1 けたの数は前に空白が 1 つ付く（` 1`）。区切りの空白 1 つと合わせて，数の間は空白 2 つに見える。

### 外側と内側の関係を確認する

`(row, col)` の順（`printf("(%d, %d)\n", row, col);` に変えて実行して確認）:

`row` が 2 になると，内側の `for` の初期化 `int col = 1` がもう一度実行されるので，`col` は 1 から始まる。
3 行 3 列では，内側の本体 9 回，内側の条件判定 12 回（各行 4 回），外側の条件判定 4 回，改行 3 回。

## 課題4　100未満の2の累乗（`Powers` / `powers.c`）

**要点**: カウンタを 1 ずつ増やして回数を決めるのではなく，**値で継続を決める**ループ。初期値 1，継続条件 `power < limit`，更新 `power *= 2`。
`for` 版と `while` 版は同じ処理で，`do-while` だけは本体を少なくとも 1 回実行する。

**解答**（`for` 版）: [Powers/powers.c](Powers/powers.c)

```c
    int limit = 100;    // 1〜100 に限定する（最後の更新でも 128 以下なので int に収まる）

    for (int power = 1; power < limit; power *= 2) {
        printf("%d, ", power);
    }
    printf("\n");       // 改行はループの後で 1 回だけ
```

**解答**（`while` 版）: [Powers/versions/powers_while.c](Powers/versions/powers_while.c)

```c
    int limit = 100;
    int power = 1;

    while (power < limit) {
        printf("%d, ", power);
        power *= 2;
    }
    printf("\n");
```

**実行結果**（`limit = 100`。両方の版で同じ。64 の後ろの `, ` の後に改行）

```text
1, 2, 4, 8, 16, 32, 64, 
```

### 境界を確かめる（両方の版で確認。テスト `Powers/limit_100`・`for_limit_*`・`while_limit_*`）

| `limit` | 表示する数 | 本体の回数 |
| ---: | --- | ---: |
| 1 | なし（改行だけ） | **0** |
| 2 | 1 | **1** |
| 64 | 1，2，4，8，16，32 | **6** |
| 65 | 1，2，4，8，16，32，64 | **7** |
| 100 | 1，2，4，8，16，32，64 | **7** |

本体の回数は `for` 版・`while` 版とも同じ（数える変数を足して確認）。条件判定は本体より 1 回多い（1, 2, 7, 8, 8 回）。
実際の表示は次のとおり（`limit = 1` は空行 1 つ）:

```text
limit=1:   (改行だけ)
limit=2:   1, 
limit=64:  1, 2, 4, 8, 16, 32, 
limit=65:  1, 2, 4, 8, 16, 32, 64, 
limit=100: 1, 2, 4, 8, 16, 32, 64, 
```

0 回（`limit = 1`）・1 回（`limit = 2`）・複数回（それ以外）の反復を区別して確かめられる。`limit = 64` と 65 は「64 が条件 `power < limit` を満たすか」の境界。

**型の範囲**: 条件を満たさなくなる直前の更新で計算する値は，`limit` が 1〜100 なら最大 128（`limit` が 65〜100 のとき 64 × 2）。
`int` は少なくとも −32767〜32767 を表せる（MSVC・GCC では 32 ビットで約 ±21 億）ので収まる。上限をむやみに大きくして `power *= 2` が `int` の範囲を超えると，
符号付き整数のオーバーフローで未定義動作になる（例えば 32 ビットの `int` で `1073741824 * 2`）。そのため `limit` を 1〜100 に限定する。

### 説明すること

**`power` が 64 のとき，本体と更新の後にどの値で条件を調べるか。**
→ 本体で `64, ` を表示した後，更新 `power *= 2` で `power` が **128** になり，`128 < limit` を調べる。`limit` が 100（や 65）なら偽なので，ループを抜けて改行を表示する。
表示しない 128 も，条件判定のために一度は計算されている。

**`<` を `<=` へ変更すると `limit = 64` の表示がどう変わるか。**
→ `64 <= 64` が真になるので 64 も表示され，`1, 2, 4, 8, 16, 32, 64, ` になる（本体 7 回。実行して確認，テスト `Powers/le_limit_64`）。
`<` のときは `64 < 64` が偽なので `1, 2, 4, 8, 16, 32, ` だった。「100**未満**」という指定には `<` が正しい。

### `do-while` との違いを確認する

[Powers/versions/powers_do_while.c](Powers/versions/powers_do_while.c)（`while` 版の `while` 全体を置き換え。`power` の初期化と後の改行は残す）

```c
    do {
        printf("%d, ", power);
        power *= 2;
    } while (power < limit);
```

| 変更した値 | 予想 | 実行結果 | そうなる理由 |
| --- | --- | --- | --- |
| `limit = 1` | `1, ` と改行 | `1, ` と改行（本体 1 回） | 条件を本体の**後**で調べるので，`1 < 1` が偽でも本体を 1 回実行してしまう |
| `limit = 100` | `1, 2, 4, 8, 16, 32, 64, ` | 同じ（本体 7 回） | 最初の条件 `1 < 100` が真の場合は，`while` と同じ回数になる |

`limit` = 2, 64, 65 も `while` 版と同じ表示だった（テスト `Powers/do_while_limit_*`）。`while` と `do-while` で結果が違うのは，**最初の条件が偽**（`limit = 1`，つまり `limit` ≦ 1）のときだけ。
この課題の「`limit = 1` ならなし（改行だけ）」という仕様は `do-while` では満たせないので，解答は `for`・`while` 版にする。

**採点のポイント・よくある誤り**

- 64 の後ろにも `, ` があり，改行は最後に 1 回だけか（各数の後で改行する，最後の区切りを省く，改行を忘れる，はいずれも指定違反）。
- 継続条件が `power <= limit` になっていないか（`limit = 64` で 64 も表示される）。
- 「`for (int i = 0; i < 7; ++i)` で 7 回繰り返す」のように回数で決めていないか。`limit` を変えると結果が合わなくなるので，課題の意図（値で継続を決める）に合わない。
  `pow` 関数（`math.h`，`double`）も講義範囲外で，この課題では使わない。
- `limit` の表の本体の回数（0, 1, 6, 7, 7）を正しく書けているか。`limit = 1` を 1 回と書いていたら `do-while` と混同している。
- `do-while` の末尾のセミコロン `} while (power < limit);` を忘れるとコンパイルエラー（MSVC: C2143 など）。
- 上限を大きくして試していないか（演習ページで禁止。符号付きオーバーフローは未定義動作）。

## 発展　`break`・`continue`・`switch` を追跡する

### 途中で飛ばす処理（`BreakContinue` / `break_continue.c`）

**要点**: `continue` は**現在の反復の残り**を飛ばして，`for` では更新式へ進む。`break` は最も内側のループを抜ける。

**解答**: [BreakContinue/break_continue.c](BreakContinue/break_continue.c)（演習ページの断片を，講義のスタイルに合わせて波括弧を改行して書いたもの）

```c
    for (int i = 0; i < 6; ++i) {
        if (i == 2) {
            continue;
        }
        if (i == 4) {
            break;
        }
        printf("%d\n", i);
    }
```

**実行前の予想と実行結果**（テスト `BreakContinue/basic`）

```text
0
1
3
```

| `i` | `i == 2` | `i == 4` | 動き |
| ---: | --- | --- | --- |
| 0 | 偽 | 偽 | `0` を表示 → 更新 `++i` |
| 1 | 偽 | 偽 | `1` を表示 → 更新 |
| 2 | **真** | （調べない） | `continue`: `printf` を飛ばして更新 `++i` へ |
| 3 | 偽 | 偽 | `3` を表示 → 更新 |
| 4 | 偽 | **真** | `break`: `for` の外へ（5 は調べない） |

**`i == 4` の `break` を `continue` に変更した結果**（テスト `BreakContinue/continue_at_4`）

```text
0
1
3
5
```

`i` が 4 のときも `printf` だけを飛ばして更新へ進み，5 を表示した後 `i` が 6 になって `6 < 6` が偽で終わる。

**説明（どちらの場合も `i == 2` の `continue` から `for` の更新へ進む）**: `continue` は「次の反復を丸ごと飛ばす」のではなく，現在の本体の残り（ここでは `i == 4` の判定と `printf`）を飛ばす。
`for` では本体の終わりへ進んだのと同じ扱いになり，更新 `++i` → 条件判定 `i < 6` の順に続く。だから `i` は 3 になり，`i == 2` で同じ場所を回り続けることはない。
これは `i == 4` の文が `break` でも `continue` でも変わらない（`i == 2` のときは `i == 4` の文まで到達しないため）。
なお同じ処理を `while` で書いて更新を本体の最後に置くと，`continue` で更新を飛ばして条件判定へ戻り，`i` が 2 のまま終わらなくなる（講義 5 節）。

**採点のポイント・よくある誤り**

- 予想を `0 1` で止める（`continue` を `break` と混同），`0 1 2 3`（`continue` を無視）などの誤り。
- `continue` の移動先を「ループの先頭（初期化）」や「条件判定」と書いていたら，`for` では**更新式**であることを指摘する。

### `switch` と `if` を比較する（`YearGroup` / `year_group.c`）

**要点**: `switch` は値が一致する `case` へ**移動して**そこから順に実行する。`case` は条件の再判定ではなく移動先のラベルなので，`break` がないと次の `case` の文へ続く（フォールスルー）。

**解答**（`switch` 版）: [YearGroup/year_group.c](YearGroup/year_group.c)

```c
    int school_year = 1;    // 入力の代わりの固定値（0〜5 に変えて確かめる）

    switch (school_year) {
    case 1:                 // 処理を書かずに次の case へ続け，1 と 2 で同じ処理を共有する
    case 2:
        printf("lower years\n");
        break;              // これがないと次の case の文へ続けて実行する（フォールスルー）
    case 3:
    case 4:
        printf("upper years\n");
        break;
    default:
        printf("invalid\n");
        break;
    }
```

**`if`・`else if`・`else` 版**: [YearGroup/versions/year_group_if.c](YearGroup/versions/year_group_if.c)

```c
    if (school_year == 1 || school_year == 2) {
        printf("lower years\n");
    } else if (school_year == 3 || school_year == 4) {
        printf("upper years\n");
    } else {
        printf("invalid\n");
    }
```

**`school_year` を 0〜5 に変えた実行結果**（両方の版で同じ。テスト `YearGroup/year_1`・`switch_year_*`・`if_year_*`）

| `school_year` | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 表示 | `invalid` | `lower years` | `lower years` | `upper years` | `upper years` | `invalid` |
| `switch` の移動先 | `default` | `case 1` | `case 2` | `case 3` | `case 4` | `default` |

**`case 1` と `case 2` の間に処理がない理由**: 1 と 2 に**同じ処理**（`lower years` の表示）を割り当てるため。`case 1:` はラベルにすぎないので，
`school_year` が 1 なら `case 1:` へ移動し，そこに文がないのでそのまま次の `case 2:` の後の `printf` を実行する。`if` 版の `school_year == 1 || school_year == 2` に当たる。
これは意図したフォールスルーで，処理の後の `break` の付け忘れとは別のもの。

**`printf` の後に `break` がある理由**: その区分の処理が終わったら `switch` の外へ抜けるため。`switch` は一致した `case` から下へ順に文を実行し，次の `case` ラベルでは止まらない。
`break` がないと，次の区分の `printf` まで実行してしまう。最後の `default` の `break` は省いても動作は同じだが，後で `case` を追加したときの付け忘れを防ぐために書いておく。

**最初の `break` を外した版**（`lower years` の後の `break;` を削除。確認後は戻す）

| 変更した値 | 予想 | 実行結果 | そうなる理由 |
| --- | --- | --- | --- |
| `school_year = 2` | `lower years` と `upper years` | `lower years`<br>`upper years` | `case 2` から実行を始め，`break` がないので次の文（`case 3`・`case 4` の後の `printf`）へ続く。`case 3` に一致したからではない |
| `school_year = 1` | 同上 | `lower years`<br>`upper years` | `case 1` → `case 2` → `case 3` の後の文と続く |
| 0, 3, 4, 5 | 元と同じ | 元と同じ | `break` を外した位置を通らない |

この版は GCC（`-Wextra` に含まれる `-Wimplicit-fallthrough`）では `this statement may fall through` の警告になる。MSVC `/W4` と Clang の `-Wall -Wextra` では警告されない（実行結果で確かめる必要がある）。

**`switch` と `if` の比較**: 結果はすべての値で同じ。`switch` は 1 つの整数の値が**定数のどれと等しいか**で分ける処理に向き，`case` を並べると区分が読みやすい。
`if` は `age <= 17` のような**範囲**や，複数の変数を使う条件も書ける（課題1 の料金分類は `switch` では書きにくい）。

**採点のポイント・よくある誤り**

- `case 1:` と `case 2:` の間に `break;` を入れて 1 で何も表示されない，`case 1: case 2:` を `case 1 || 2:` と書く（`1 || 2` は 1 なので `case 1:` と同じになり，2 が `invalid` になる）。
- `if` 版を `school_year == 1 || 2` と書く誤り（`|| 2` は常に真なので，どの値も `lower years` になる）。
- 「`case 3` に一致したから `upper years` が出た」という説明は誤り。`case` は移動先で，移動した後は条件を調べずに順に実行する。
- 2 つの理由（`case` の共有と `break`）を別々に説明できているか。

## 確認問題

**1. `if (3)` は真・偽のどちらの経路へ進むか。**

結論: **真**の経路へ進む。
理由: C の条件は 0 が偽，0 以外がすべて真。3 は 0 ではないので真（`if (3)` の後の本体が実行されることを実行して確認）。比較の結果の 0・1 だけが条件になるわけではない。

**2. `flag` が −1 の場合，`if (flag)`，`if (!flag)`，`if (flag == 1)` はそれぞれ真か偽か。**

結論: `if (flag)` は**真**，`if (!flag)` は**偽**，`if (flag == 1)` は**偽**。
理由: `if (flag)` は `if (flag != 0)` と同じで，−1 は 0 ではないので真。`!flag` は `flag` が 0 のときだけ 1 になるので，−1 では 0（偽）。`flag == 1` は −1 と 1 が等しくないので 0（偽）。
「真」と「1 と等しい」は違う（実行して確認）。

**3. `for (int i = 0; i < 3; ++i)` の本体と条件判定はそれぞれ何回か。**

結論: **本体 3 回，条件判定 4 回**（数える変数を足して確認）。
理由: `i` = 0, 1, 2 で条件が真になって本体を実行し，更新で `i` が 3 になった 4 回目の判定 `3 < 3` が偽で抜ける。初期化は 1 回，更新は 3 回。

**4. `while` と `do-while` の本体の実行回数が異なるのは，どのような開始条件か。**

結論: **最初の条件判定が偽になる**（開始時に条件を満たさない）とき。`while` は 0 回，`do-while` は 1 回になる。
理由: `while` は本体の前に条件を調べ，`do-while` は本体の後で調べるから。課題4 の `limit = 1`（`1 < 1` が偽）で，`while` 版は改行だけ，`do-while` 版は `1, ` を表示した。
最初の条件が真なら，どちらも同じ回数（`limit = 100` で 7 回）。

**5. `for` の `continue` はどこへ進むか。`while` ではどうか。**

結論: `for` では**更新式**（`++i` など）へ進み，その後で条件判定をする。`while` では**条件判定**へ直接進む。
理由: `for` の更新は本体の後に自動で行われる部分なので，`continue` で本体の残りを飛ばしても実行される（発展の `i == 2`）。
`while` の更新は本体の中に自分で書いた文なので，それが `continue` より後にあると飛ばされ，同じ値のまま条件へ戻って無限ループになることがある。`do-while` では末尾の条件判定へ進む。

**6. 3 行 4 列の二重ループで，内側が毎回 1 回目に `break` したら，本体は合計何回か。**

結論: 内側のループの本体は**合計 3 回**（外側の各反復で 1 回ずつ）。外側の本体も 3 回。
理由: `break` は最も内側のループだけを抜けるので，外側のループは続き，3 行分すべて内側のループが始まる。それぞれ 1 回目の本体で `break` するので 3 × 1 = 3 回（`break` より前の文は 3 回，後の文は 0 回）。
数える変数を足して確認した（外側 3 回，内側 3 回）。`break` がなければ 3 × 4 = 12 回。

**7. `switch` の `default` がなく，一致する `case` もないとき，どこへ進むか。**

結論: `switch` の中の文を何も実行せず，**`switch` の後の文**へ進む。
理由: `default` はどの `case` にも一致しない場合の移動先で，省略すると移動先がないため（講義 5 節）。エラーにはならず，プログラムも終了しない。

**8. 講義の `goto` の例で `goto done;` を `break;` に置き換えても同じ表示になるのはなぜか。**

結論: ラベル `done:` が `for` の**直後**にあるので，`goto done;` の移動先と，`break;` で `for` を抜けた先が同じ文（`printf("done\n");`）になるから。
理由: `n` が 3 のとき，`goto` は `done:` へ移動し，`break` は最も内側のループ（この `for`）の外，つまり直後の文へ進む。どちらも `0`・`1`・`2` を表示した後 `done` を表示する（両方を実行して確認）。
ループが二重で `done:` が外側のループの後にある場合や，ラベルがループの直後でない場合は，`break` では同じにならない。
