# BugGrade　点数から評価を決める（第5回）

ソース: [grade.c](grade.c)

## 対象の回と前提

- 第5回（配列と関数）。点数を受け取って評価の文字を返す関数 `grade` を，配列の各要素について呼ぶ。条件の順序は第4回の講義 2 節「複数の条件を上から調べる」と課題1 `Fee` の続き。
- 学生が知っていること: 関数の定義・プロトタイプ宣言・戻り値，配列，`char` と `%c`（第2回），`if`／`else if`，ブレークポイント（F9）・F5・F10・**Locals**。
- 関数の中へ入るステップイン（F11）は授業では未習（第14回の講義）。この題材では使わなくても探せる。

## プログラムがするはずのこと

点数（0〜100）ごとに評価を表示する。80 以上は A，70 以上は B，60 以上は C，60 未満は D。期待する表示:

```text
 95: A
 80: A
 74: B
 60: C
 59: D
  0: D
```

## 症状

**Startup Item** で `debugging BugGrade` を選び，Ctrl+F5 で実行する。

```text
 95: C
 80: C
 74: C
 60: C
 59: D
  0: D
```

60 以上はすべて C になる（テスト `debugging/BugGrade/symptom`）。D の 2 行は正しい。

## 学生への渡し方

- 渡すもの: `grade.c` だけ。
- 最初に言うこと: 「点数から A〜D を表示するプログラムです。95 と 80 は A，74 は B と出るはずですが，Ctrl+F5 で実行すると 60 以上がすべて C と出ます。原因をデバッガで探してください」
- 言わないこと: 条件の順序。

## 探し方

1. **症状を分類する**: 正しい行（59・0 → D）と誤った行（60 以上がすべて C）に分ける。「C を返す `return` を，A・B のはずの点数も通っている」と範囲を絞る。
2. **関数の中で止める**: `grade` の最初の `if (score >= 60) {` の行に F9 を置き，F5。F5 は `main` のループから `grade` が呼ばれたところで止まる（ステップインを使わなくても，呼ばれた関数の中のブレークポイントで止まる）。
3. **Locals** で `score` が 95 であることを確かめ，F10 を 1 回押す。次の行が `return 'C';` になる。
4. **仮説**: 「95 は最初の条件 `score >= 60` で真になり，後ろの `score >= 80` まで調べられない」。
5. **確かめる**: 条件を上から順に，`score = 95` を当てはめて真・偽を言わせる。真になった最初の枝だけが実行されることを確かめる。2 つ目・3 つ目の枝（B・A）には，どんな点数でも到達できないことにも気付かせる。

## ヒントの段階

1. 「95 を渡したとき，`grade` はどの行の `return` で返っている？」
2. 「`if`／`else if` は，真になった枝の後ろの条件も調べる？」
3. 「`score >= 70` の枝に入れる点数はある？ その前の条件で全部取られていない？」

## 原因

`else if` の連なりは上から調べ，最初に真になった枝だけを実行する。下限が小さい条件（`score >= 60`）を先に書いたので，60 以上の点数はすべて最初の枝で C になり，`score >= 70`・`score >= 80` の枝には到達できない。
下限で区切るときは，条件の厳しい（下限の大きい）順に並べる（第4回 講義 2 節「複数の条件を上から調べる」）。

## 直し方

```diff
-    if (score >= 60) {
-        return 'C';
-    } else if (score >= 70) {
-        return 'B';
-    } else if (score >= 80) {
-        return 'A';
-    }
+    if (score >= 80) {
+        return 'A';
+    } else if (score >= 70) {
+        return 'B';
+    } else if (score >= 60) {
+        return 'C';
+    }
```

直した版は期待する 6 行を表示する（テスト `variant_fixed`）。

## 学生への問い

- 問「A になるはずの点数を 1 つも試していなかったら気付けた？」→ 気付けない。C と D の境目（60・59）だけでは正しく見える。評価ごとに 1 つ以上と，各境界（80・79・70・69・60・59）を試す。
- 問「`score >= 60 && score < 70` のように範囲を両側から書けば，順序は関係ない？」→ 関係なくなるが，境界を 2 回ずつ書くので書き間違いの場所が増える。上から順に調べる書き方では順序が仕様の一部になる。
- 問「コンパイラは警告を出さなかった。なぜ？」→ どの条件も文法として正しく，到達しない枝があるかは値の範囲を考えないと分からないから。
