# BugFactorialOverflow　大きな階乗（第14回）

ソース: [factorial.c](factorial.c)

> [!IMPORTANT]
> この題材の誤りは `int` の**桁あふれ**（符号付き整数のオーバーフロー）で，C では**未定義動作**。下の表示は Linux の GCC・Clang で実際に実行したもので，Windows の MSVC でも同じ値（2 の 32 乗で回り込んだ値）になることが多いが，保証はない。
> 未定義動作なので，バグ入りの版は自動テストで実行しない（直した版だけをテストする）。

## 対象の回と前提

- 第14回（再帰）。講義 3.1「階乗の型と上限」と，課題1「階乗の境界」の後。`int` の範囲（第2回・第6回）の復習。
- 学生が知っていること: 再帰関数，`int`・`long long`・`unsigned long long` と `printf` の書式，ブレークポイント（F9）・F5・F10・F11・**Locals**・**Call Stack**。**Autos** と条件付きブレークポイントは授業では未習。
- 入力も引数もない。

## プログラムがするはずのこと

0 から 15 までの `n` について，再帰関数 `factorial` で `n!` を求めて表示する。期待する表示の最後の 4 行:

```text
12! = 479001600
13! = 6227020800
14! = 87178291200
15! = 1307674368000
```

## 症状

**Startup Item** で `debugging BugFactorialOverflow` を選び，Ctrl+F5 で実行する。0! から 12! までは正しく，13! から誤る。

```text
12! = 479001600
13! = 1932053504
14! = 1278945280
15! = 2004310016
```

異常終了もダイアログもなく，もっともらしい数が並ぶ（Debug・Release とも同じ表示だった）。13! が 12! の 13 倍より小さく，14! が 13! より小さいことから誤りと分かる。
UndefinedBehaviorSanitizer 付き（`-DSOFTPRAC_SANITIZE=ON`）では，最初の桁あふれで次の報告が出る（表示はそのまま続く）:

```text
.../factorial.c:11:14: runtime error: signed integer overflow: 13 * 479001600 cannot be represented in type 'int'
```

## 学生への渡し方

- 渡すもの: `factorial.c` だけ。
- 最初に言うこと: 「0! から 15! までを表示するプログラムです。15! は 1307674368000 と出るはずですが，Ctrl+F5 で実行すると 2004310016 と出ます。13! から違います。原因をデバッガで探してください」
- 言わないこと: `int` の範囲，型を広げること。

## 探し方

1. **境目を探す**: 12! までは正しく，13! から誤る。「13! の計算で何かが起きる」と範囲を絞る。13! = 13 × 12! を手で（電卓で）計算させ，6227020800 であることを確かめる。
2. **止めて値を見る**: `factorial` の `return n * factorial(n - 1);` の行に F9 を置くと何度も止まるので，`main` の `printf` の行に F9 を置き，F5 を押して **Locals** の `n` が 13 になるまで進める（F5 を 14 回押す。ブレークポイントを右クリックして **Conditions** で `n == 13` を指定すれば 1 回で止まる。条件付きブレークポイント。授業では未習，[practice/README.md](../../practice/README.md) の第4回の「デバッグの補足」）。そこで F11（**Debug > Step Into**）で `factorial` に入り，`return` の行で F10 を押しながら，戻ってきた値を見る（**Debug > Windows > Autos**（授業では未習）に `factorial` の戻り値が出る）。`n` が 13 の呼び出しで，479001600 に 13 を掛けた結果が 1932053504 になる。
3. **仮説**: 「6227020800 は `int` に入らない。`int` で計算しているので，積が範囲を超えた」。
4. **確かめる**: `int` の最大値（Windows・Linux の一般的な環境では 2147483647。`<limits.h>` の `INT_MAX`）と 6227020800 を比べ，13! が `int` に入らないことを確かめる。`factorial` の戻り値の型と，掛け算 `n * factorial(n - 1)` の型がどちらも `int` であることを言わせる。

## ヒントの段階

1. 「何! から違う？ 13! は 12! の何倍になるはず？」
2. 「13! = 6227020800 は，`int` で表せる？ `int` の最大値はいくつ？」
3. 「`factorial` の戻り値の型は？ 掛け算はどの型で計算される？」

## 原因

`factorial` が `int` を返し，掛け算 `n * factorial(n - 1)` も `int` で計算する。13! = 6227020800 は `int` の最大値 2147483647（32 ビットの `int`）を超えるので，13 × 479001600 の時点で桁あふれする。
符号付き整数の桁あふれは未定義動作で，多くの環境では 2 の 32 乗で割った余りのような値に回り込んで，誤った値がそのまま表示される（講義 3.1「小さな値へ回り込んだ出力を正解として扱わないように，計算前に範囲を検査します」）。
コメントの範囲「0〜15」に対して型の上限（`int` では 12! まで）を確かめていなかったことが根本の原因。値はコンパイル時に分からない（再帰の中の掛け算）ので，コンパイラの警告では見つからない。

## 直し方

15! まで表せる型で計算する。

```diff
-int factorial(int n)
+long long factorial(int n)
```

```diff
-        printf("%2d! = %d\n", n, factorial(n));
+        printf("%2d! = %lld\n", n, factorial(n));
```

戻り値が `long long` になると，`n * factorial(n - 1)` は `n` も `long long` へ変換して計算する。直した版は 0! から 15! までを正しく表示する（テスト `variant_fixed`）。
講義 3.1 と同じく `unsigned long long`（`%llu`）にしてもよい。どちらの型でも 21! は入らないので，範囲を 0〜20 に決め，範囲外の `n` は再帰に入る前に拒否する（課題1・課題4）。

## 学生への問い

- 問「戻り値の型だけ `long long` にして，`printf` の書式を `%d` のままにしたら？」→ 書式と引数の型が合わず未定義動作（GCC・Clang は `-Wall` で，MSVC は C4477 で警告する）。型を変えたら書式も変える。
- 問「`int` のまま，15! の代わりに 12! までにすれば正しい？」→ 正しい。範囲を型に合わせるか，型を範囲に合わせるかのどちらかで，範囲と型を一緒に決めることが大事。
- 問「異常終了しないのに，どうやって誤りに気付く？」→ 期待値を先に書く（13! = 6227020800），隣の値との関係（13! = 13 × 12!）を確かめる，境界（型の上限の前後）を必ず試す。
