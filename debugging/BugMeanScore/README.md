# BugMeanScore　点数の平均（第5回）

ソース: [mean_score.c](mean_score.c)

## 対象の回と前提

- 第5回（配列と関数）。配列と要素数を受け取り，平均を `double` で返す関数 `mean_score`。発展 `SumMean` の「平均では `(double)total / n` とし，整数除算を避けます」と，講義 6 節の `total / 5.0` の理由（整数除算を避ける）に結び付く。発展の前でも後でも渡せる（発展を終えた学生には，自分の `SumMean` との違いを言わせる）。第6回の課題3 `Average` の前の復習にも使える。
  誤りの形は第3回 講義 3 節の例 `double result = 7 / 2;` と同じで，発展 `SumMean` の本文に直し方が書いてある。コードを読んで当てた学生にも，デバッガで `mean` が 77 になる瞬間を見せてから原因を言わせる（共通ルールの「表を見て当てるのではなく」と同じ）。
- 学生が知っていること: 関数の定義・プロトタイプ宣言・戻り値の型，配列を引数で渡すこと（`const int a[]` と要素数 `n`），`%.1f`，整数同士の割り算は小数部を切り捨てること（第3回 講義 3 節），ブレークポイント・デバッグ実行・ステップオーバー・ローカル変数（第4回 講義 7 節。キー F9・F5・F10 と，F5 で次のブレークポイントまで進む **Debug > Continue** は授業資料に出ないので，TA が最初に見せる）。
- 関数の中へ入るステップイン（F11）は授業では未習（第14回の講義）。この題材では使わなくても探せる。入力も引数もない。

## プログラムがするはずのこと

配列 `{70, 85, 90}` の先頭の `n` 個（`n` = 1〜3）の平均を，小数第 1 位まで表示する。期待する表示:

```text
n=1 mean=70.0
n=2 mean=77.5
n=3 mean=81.7
```

## 症状

**Startup Item** で `debugging BugMeanScore` を選び，Ctrl+F5 で実行する。

```text
n=1 mean=70.0
n=2 mean=77.0
n=3 mean=81.0
```

`n` = 1 は正しく，`n` = 2・3 は小数部がいつも `.0` になる（テスト `debugging/BugMeanScore/symptom`）。

## 学生への渡し方

- 渡すもの: `mean_score.c` だけ。
- 最初に言うこと: 「配列の先頭から 1 個，2 個，3 個の点数の平均を出すプログラムです。70.0，77.5，81.7 と出るはずですが，Ctrl+F5 で実行すると 70.0，77.0，81.0 と出ます。原因をデバッガで探してください」
- 言わないこと: 整数の割り算・型の変換の話。

## 探し方

1. **症状を分類する**: 正しい行（`n` = 1。70 ÷ 1 は割り切れる）と誤った行（77.5 が 77.0，81.67 が 81.0）に分ける。「割り切れないときだけ違う」「小数部がいつも 0」と言わせる。
2. **関数の中で止める**: `mean_score` の `return mean;` の行に F9 を置き，F5。F5 は `main` のループから `mean_score` が呼ばれたところで止まる（ステップインを使わなくても，呼ばれた関数の中のブレークポイントで止まる）。1 回目（`n` = 1）は正しいので，もう一度 F5（**Debug > Continue**）で `n` = 2 の回へ進む。
3. **Locals** で `n` = 2，`sum` = 155 を確かめる。155 ÷ 2 は 77.5 のはずだが，`mean` は `77.000000000000000` のように小数部が 0 になっている。**Locals** の **Type** 列で `mean` が `double` であることを見る（型は小数部を表せるのに 77.0 になっている）。
4. **仮説**: 「`sum / n` は `int` どうしの割り算なので，割った時点で 77 に切り捨てられ，その 77 を `double` に入れているだけ」。
5. **確かめる**: Shift+F5 で止め，ブレークポイントを `double mean = sum / n;` の行に移して F5，もう一度 F5（**Debug > Continue**）で `n` = 2 の回で止める。F10 で 1 行進め，`mean` が 77 になる（代入の時点ですでに 77。戻り値で落ちるのではない）ことを見る（止まった時点の `mean` はまだ計算されていないので，`-9.2559631349317831e+61` のような値が見えても読まない）。
   **Watch 1**（授業では未習）を使えるなら `sum / n` と `sum / 2.0` を並べて書き，77 と 77.5 になることを見る。使わない場合は，講義 6 節の `total / 5.0` と同じく割る数を `2.0` にした式の値を紙で答えさせる。

## ヒントの段階

1. 「`n` = 2 のとき，`sum` はいくつ？ `sum / n` を C の規則で計算するといくつ？」
2. 「`sum` と `n` の型は？ 割り算の結果の型はどちらで決まる？」
3. 「`double mean = …;` の右辺は，代入の前と後のどちらで計算される？ 77.5 は右辺の時点でもう失われていない？」

## 原因

`sum` と `n` はどちらも `int` なので，`sum / n` は整数の割り算になり，小数部を切り捨てた `int`（155 / 2 は 77）になる。その後で `double mean` に代入するので 77.0 になる。
代入先が `double` でも，右辺の計算の型は右辺のオペランドの型だけで決まる（第3回 講義 3 節「整数同士の割り算」，第5回 講義 6 節の `total / 5.0` の理由）。

`int` から `double` への変換は値を失わないので，MSVC `/W4` も GCC・Clang の `-Wall -Wextra -Wpedantic` も警告を出さない（失われるのは割り算の時点で，変換の時点ではない）。

## 直し方

```diff
-    double mean = sum / n;
+    double mean = (double)sum / n;
```

直した版は `70.0`・`77.5`・`81.7` を表示する（テスト `variant_fixed`）。割る前に一方のオペランドを `double` にすれば，もう一方も `double` に変換されて小数の割り算になる（発展 `SumMean` の `(double)total / n` と同じ形。`(double)` の型変換は第6回の講義で詳しく扱う）。

## 学生への問い

- 問「`n` = 1 だけで試していたら気付けた？ `{80, 90}` の 2 個なら？」→ どちらも気付けない（70 ÷ 1，170 ÷ 2 は割り切れる）。割り切れない組を 1 つ以上試す。割り切れないことがある最小の `n` は 2 なので，この誤りを捕まえる最小の入力は `n` = 2 の `{70, 85}`（期待 77.5，誤りの版では 77.0）。
- 問「`double mean = (double)(sum / n);` に直したら？」→ 直らない。かっこの中の整数の割り算が先に計算されて 77 になり，それを `double` にするだけ。変換は割る**前**に要る（第6回 課題3 `Average` の「説明すること」と同じ問い。第5回では答えを確かめるだけにし，型変換の説明は第6回に回す）。
- 問「関数の戻り値の型を `double` にしたのに，なぜ小数部が消えた？」→ 戻り値の型は返す値を変換するだけで，`return` より前の計算の型は変えないから。型は「どの値を，どこで」変換するかを組で考える。
