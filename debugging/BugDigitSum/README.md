# BugDigitSum　各桁の和（第6回）

ソース: [digit_sum.c](digit_sum.c)

## 対象の回と前提

- 第6回（文字列）。講義 1 節「1文字は整数としても読める」と，ウォームアップ `CharCode`（`c - '0'`）の後。
- 学生が知っていること: `char` 配列の文字列と終端 `'\0'`，文字は文字コード（整数）として計算できること，ブレークポイント（F9）・F5・F10・**Locals**。
- 入力も引数もない。

## プログラムがするはずのこと

数字だけからなる文字列 `"2024"` の各桁を数として足し，`sum=8`（2 + 0 + 2 + 4）と表示する。

## 症状

**Startup Item** で `debugging BugDigitSum` を選び，Ctrl+F5 で実行する。

```text
sum=200
```

期待は `sum=8`（テスト `debugging/BugDigitSum/symptom`）。

## 学生への渡し方

- 渡すもの: `digit_sum.c` だけ。
- 最初に言うこと: 「文字列 "2024" の各桁を足すプログラムです。`sum=8` と出るはずですが，Ctrl+F5 で実行すると `sum=200` と出ます。原因をデバッガで探してください」
- 言わないこと: 文字コード，`'0'`。

## 探し方

1. **症状から見当を付ける**: 200 は 8 より 192 大きい。4 桁で 192，1 桁あたり 48。この 48 が何かを考えさせる（気付かなくてよい。次へ進む）。
2. **1 回目で止める**: `sum += digits[i];` の行に F9，F5。**Locals** の `digits` を展開すると，各要素が `50 '2'` のように文字コードと文字の組で表示される。
3. F10 を 1 回押して `sum` を見る。2 ではなく 50 が足されている。
4. **仮説**: 「`digits[i]` は数の 2 ではなく，文字 `'2'` の文字コード 50。数字の文字を数にする変換をしていない」。
5. **確かめる**: `'0'` の文字コードを **Locals**（`digits[1]`）で確かめ（48），「`'2'` − `'0'` は？」と聞く（2）。数字の文字コードが `'0'`〜`'9'` の順に 48〜57 と並ぶことを，ASCII の表（課題2 `AsciiTable`）で確かめる。

## ヒントの段階

1. 「1 回目の足し算の後，`sum` はいくつ？ 2 になった？」
2. 「**Locals** で `digits[0]` を見よう。`'2'` の横に出ている数は何？」
3. 「`'0'` の文字コードはいくつ？ `'2'` から `'0'` を引くと？」

## 原因

`digits[i]` は文字 `'2'` の文字コード（ASCII で 50）で，数の 2 ではない。数字の文字の文字コードは `'0'`〜`'9'` の順に連続しているので，`digits[i] - '0'` で数 0〜9 にする（講義 1 節，ウォームアップ `CharCode` の `c - '0'`）。
`char` は整数型なので `int` に足すことは文法上正しく，コンパイラは警告を出さない。

## 直し方

```diff
-        sum += digits[i];
+        sum += digits[i] - '0';
```

直した版は `sum=8` を表示する（テスト `variant_fixed`）。

## 学生への問い

- 問「`sum += digits[i] - 48;` と書いても同じ結果になる。なぜ `'0'` と書く方がよい？」→ 48 が何の数か読み手に分からない。`'0'` なら「数字の文字を数にする」意図が読める（文字コードの表を覚えていなくてよい）。
- 問「`"20a4"` のように数字以外が混ざっていたら？」→ `'a' - '0'` は 49 になり，誤った和になる。足す前に `digits[i] >= '0' && digits[i] <= '9'` を確かめる（`CharCode` と同じ）。
- 問「`"0000"` で試したら気付けた？」→ 気付ける（期待 0，誤りの版は 192）。ただし「0 になるはず」を先に書いていればの話で，期待値を先に書く習慣が効く。
