# BugSkipCount　3 の倍数を飛ばす（第4回）

ソース: [skip_count.c](skip_count.c)

## 対象の回と前提

- 第4回（制御構造）。講義 4 節「無限ループと停止条件」と 5 節「`break`・`continue`」の後。発展の「途中で飛ばす処理」と同じ形の誤り。
- 学生が知っていること: `while`・`if`・`continue`・`%`，ブレークポイント（F9），デバッグ実行（F5），ステップオーバー（F10），**Locals**，**Debug > Stop Debugging**。
- 入力も引数もない。

## プログラムがするはずのこと

1 から `n`（= 10）までの整数のうち 3 の倍数でないものを 1 行に 1 つ表示し，最後に個数を表示する。期待する表示:

```text
1
2
4
5
7
8
10
count=7
```

## 症状

**Startup Item** で `debugging BugSkipCount` を選び，Ctrl+F5 で実行する。

```text
1
2
```

の 2 行が出た後，何も表示されず終わらない（コンソールを閉じるか Ctrl+C で止める）。Windows でも Linux でも同じ。
終わらないので，このプログラムの自動テストは直した版だけにしている。

## 学生への渡し方

- 渡すもの: `skip_count.c` だけ。
- 最初に言うこと: 「3 の倍数を飛ばして表示し，最後に個数を出すプログラムです。1 と 2 が出た後，止まったまま終わりません。今どの行を繰り返しているのか，そのとき変数はいくつかを，デバッガで確かめてください」
- 言わないこと: `continue` の話。「`i` が変わっていない」も学生が見つけるまで言わない。

## 探し方

1. **症状から範囲を絞る**: 最後に出たのは `2`。次に表示されるはずの `4` が出ないので，「`i` が 3 のあたりで何かが起きている」と見当を付けさせる。
2. **止めて今の場所を見る**: F5 で実行し，止まったら **Debug > Break All**（授業では未習。初めて見せる）で一時停止する。黄色の矢印が `while` のループの中にあり，**Locals** の `i` が 3，`count` が 2 であることを見る。
   （**Break All** を使わない場合は，`if (i % 3 == 0) {` の行に F9 を置いて F5 で実行する。）
3. **1 文ずつ進める**: F10 を数回押し，`if` → `continue` → `while` の条件 → `if` … と同じ行だけを回り，`printf` と `++i` の行へ一度も進まないことを確かめる。**Locals** の `i` は 3 のまま変わらない。
4. **仮説**: 「`i` が 3 のとき，`continue` で `++i` を飛ばしているので，`i` が増えず条件が真のまま」。
5. **確かめる**: 「`continue` の次に実行されるのはどの行か」を，F10 の 1 回分で答えさせる（`while` の条件。`++i` ではない）。確かめたら Shift+F5（**Debug > Stop Debugging**）。

## ヒントの段階

1. 「止まっているとき，`i` はいくつ？ F10 を何回か押して，`i` は変わる？」
2. 「`continue` の後，次に実行される行はどこ？ `++i` を通っている？」
3. 「`while` では，更新 `++i` はどこに書いてある？ 3 の倍数のときもそこを通る？」

## 原因

`while` は `for` と違い，更新（`++i`）を自分で本体に書く。`continue` は本体の残りを飛ばして条件の判定へ戻るので，3 の倍数のときは `++i` が実行されず，`i` が 3 のまま条件 `i <= n` が真であり続ける（講義 7 節の表「終了しない：更新忘れ，`continue`で更新を飛ばした」）。

## 直し方

`continue` の前でも `i` を更新する（最小の変更）。

```diff
         if (i % 3 == 0) {
+            ++i;
             continue;
         }
```

直した版は期待する 8 行を表示する（テスト `variant_fixed`）。
更新を 1 か所にまとめたいなら，`for (int i = 1; i <= n; ++i)` に書き換えて本体の `++i` を消す（`for` の `continue` は更新 `++i` へ進む）。

## 学生への問い

- 問「同じ処理を `for` で書いていたら，この誤りは起きた？」→ 起きない。`for` の `continue` は更新式へ進んでから条件を調べるから。
- 問「止まらないプログラムに気付いたら，まず何をする？」→ 止まっている場所と変数の値を見る（**Break All** か，ループ内のブレークポイント）。そのうえで「どの変数が変わらないので条件が偽にならないか」を探す。
- 問「`n = 2` でテストしていたら気付けた？」→ 気付けない。3 の倍数が出てこないので `continue` を通らない。誤りの経路を通る値（3 以上）を選ぶ。
