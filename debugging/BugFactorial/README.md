# BugFactorial　階乗の表（第14回）

ソース: [factorial.c](factorial.c)

> [!IMPORTANT]
> この題材は再帰が止まらず，スタックを使い切って**異常終了**する。止まり方は環境・構成で変わる。下の MSVC の症状は，スタックオーバーフローの例外（0xC00000FD）の扱いから通常見られるもの（授業の前に TA が手元で一度確かめる）。Linux の症状は GCC で実際に実行したもの。
> 最適化した構成（Release）では，再帰が繰り返しに変換されて異常終了しなくなることがある（Release 構成（`-O3`）の GCC ではすぐに `0! = 0` を表示し，Clang では 10 秒たっても終わらなかった）。Debug 構成で扱う。

## 対象の回と前提

- 第14回（再帰）。講義 1.2「入力の範囲も停止の根拠に含める」，1.3「設計の4つの問い」，講義 5.2 の Visual Studio での観察手順（**Call Stack**）の後。課題1「階乗の境界」の続き。
- 学生が知っていること: 再帰関数・基底条件・呼び出しと復帰，ブレークポイント（F9）・F5・F10・ステップイン（F11）・**Locals**・**Call Stack**（講義 5.2）。
- 入力も引数もない。

## プログラムがするはずのこと

0 から 5 までの `n` について，再帰関数 `factorial` で `n!` を求めて表示する（`0! = 1`）。期待する表示:

```text
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
```

## 症状

**Startup Item** で `debugging BugFactorial` を選び，Ctrl+F5 で実行する。

- 何も表示されずに異常終了する。Debug 構成の MSVC では，コンソールの最後に `exited with code -1073741571`（0xC00000FD：スタックオーバーフロー）のように表示される。
- F5（**Debug > Start Debugging**）で実行すると，**Exception Unhandled** のウィンドウに `0xC00000FD: Stack overflow` と出て，`factorial` の中で止まる。
- Linux の GCC（Debug）: 何も表示せず `Segmentation fault` で終わる（終了コード 139）。AddressSanitizer 付きでは `AddressSanitizer: stack-overflow` と，`factorial` が何段も並ぶ呼び出し履歴を表示する。

正しい表示にならず異常終了するので，バグ入りの版は自動テストで実行しない（直した版だけをテストする）。

## 学生への渡し方

- 渡すもの: `factorial.c` だけ。Debug 構成で実行するように言う。
- 最初に言うこと: 「`0! = 1` から `5! = 120` までの 6 行を表示するプログラムです。Debug 構成で Ctrl+F5 で実行すると，1 行も出ずに異常終了します。原因をデバッガで探してください」
- 言わないこと: 基底条件が `n == 1` であること。

## 探し方

1. **症状から範囲を絞る**: 1 行目の `0! = 1` すら出ない。`printf` の引数の `factorial(0)` が戻ってこないと見当を付ける（`printf` は引数をすべて計算してから表示する）。
2. **止まった場所を見る**: F5 で実行し，例外で止まったら **Debug > Windows > Call Stack** を開く。`factorial` が何千段も並ぶ（深すぎるので途中で表示が打ち切られ，`main` まで見えないこともある）。
3. **値を見る**: いちばん上の `factorial` の **Locals** の `n` を見る（−5000 のような大きな負の数。値は環境で変わる）。**Call Stack** の 2 行目・3 行目をダブルクリックして `n` を見ると，1 段下がるごとに 1 ずつ大きい（−4999，−4998 …）。0 から 1 ずつ減りながら呼び続けたことが分かる。
4. **仮説**: 「`factorial(0)` は基底条件 `n == 1` に当てはまらず，`factorial(-1)`，`factorial(-2)` … と 1 に近づかずに呼び続けている」。
5. **確かめる**: Shift+F5 で止め，`factorial` の `if` の行に F9 を置いて F5 → 最初の停止で `n` が 0，F11（**Debug > Step Into**）で次の呼び出しに入ると `n` が -1 になることを見る。講義 1.3 の問い「再帰せず答えが分かる最小の場合は何か」に，範囲 0〜12 を当てはめさせる（0）。

## ヒントの段階

1. 「F5 で実行して止まったところで，**Call Stack** には `factorial` が何段ある？ `n` はいくつ？」
2. 「`factorial(0)` を呼ぶと，次に何を呼ぶ？ その次は？」
3. 「範囲 0〜12 のうち，再帰せずに答えが分かる最小の `n` はいくつ？ 基底条件はそれになっている？」

## 原因

基底条件が `n == 1` なので，範囲の最小値 `n = 0` で基底条件に当たらず，`n - 1` で −1，−2 … と離れていく。再帰が止まらず，呼び出しのたびに積まれるスタックフレームでスタックを使い切って異常終了する（講義 4 節「スタックと呼び出し深さ」）。
1〜12 では正しく動くので，0 を試さないと気付けない。基底条件は「範囲の最小の場合」にし，すべての入力がそこへ近づくことを確かめる（講義 1.2・1.3）。

## 直し方

```diff
-    if (n == 1) {
+    if (n == 0) {
         return 1;
     }
```

直した版は `0! = 1` から `5! = 120` までを表示する（テスト `variant_fixed`）。`n <= 1` でも同じ結果になる。範囲外（負の数・13 以上）の入力は，課題4 のように再帰に入る前に呼び出し側で拒否する。

## 学生への問い

- 問「1! から 5! までしか試していなかったら気付けた？」→ 気付けない。0 のときだけ基底条件を通り越す。範囲の最小値（境界）を必ず試す。
- 問「なぜ無限ループのように『止まらない』ではなく，異常終了した？」→ 再帰は呼び出しのたびにスタックフレームを積み，戻らないので積み続けて上限に達するから。繰り返しの無限ループはスタックを使わないので止まらないだけ。
- 問「`factorial(-1)` を呼ばれたら，直した版はどうなる？」→ やはり止まらない（0 に近づかない）。範囲外の値を関数の入口か呼び出し側で拒否する必要がある（課題4「再帰の入口を安全にする」）。
