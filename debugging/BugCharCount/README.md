# BugCharCount　ファイルの文字数と行数（第10回）

ソース: [char_count.c](char_count.c)，入力: [input.txt](input.txt)，既定の引数: [run.args](run.args)（`input.txt`）

## 対象の回と前提

- 第10回（ファイル）。講義 1 節・3 節の `fgetc` と `EOF`，`feof` の注意（「`while (!feof(fp))` で先に終了を予測するのではなく，読み取り関数の戻り値でループを制御します」）の後。
- 学生が知っていること: `fopen`・`fgetc`・`fclose`・`feof`・`ferror`，コマンドライン引数（**Configuration Properties > Debugging > Command Arguments**），ブレークポイント（F9）・F5・F10・**Locals**。
- 引数でファイル名を受け取る。

## プログラムがするはずのこと

引数で指定したテキストファイルを 1 文字ずつ読み，文字数（改行も 1 文字）と行数（改行の数）を表示する。`input.txt`（`apple`・`banana`・`cherry` の 3 行，改行を含めて 20 文字）なら:

```text
chars=20 lines=3
```

## 症状

**Startup Item** で `debugging BugCharCount  [input.txt]` を選び（作業ディレクトリは題材のフォルダ，引数は `input.txt`），Ctrl+F5 で実行する。

```text
chars=21 lines=3
```

文字数が 1 多い。空のファイルを渡すと `chars=1 lines=0`（期待は `chars=0 lines=0`）。行数は正しい（テスト `debugging/BugCharCount/three_lines`・`empty_file`）。
Windows ではテキストモードで改行（CR LF）が 1 文字 `'\n'` として読まれるので，`input.txt` の改行が CR LF でも LF でも同じ表示になる。

## 学生への渡し方

- 渡すもの: `char_count.c` と `input.txt`。`input.txt` はプロジェクトフォルダに置き，**Command Arguments** を `input.txt` にするよう伝える。
- 最初に言うこと: 「ファイルの文字数と行数を数えるプログラムです。**Command Arguments** を `input.txt`（3 行，改行を含めて 20 文字）にして Ctrl+F5 で実行すると，`chars=20 lines=3` と出るはずですが，`chars=21 lines=3` と出ます。空のファイルでも `chars=0` のはずが `chars=1` と出ます。原因をデバッガで探してください」
- 言わないこと: `feof` の意味・戻り値で判定すること。

## 探し方

1. **入力を小さくする**: 空のファイル（メモ帳で作った 0 バイトの `empty.txt`）を引数にして再現させる。「1 文字も読めないはずなのに，ループの本体が 1 回実行されている」と範囲が絞れる。
2. **止めて値を見る**: `++chars;` の行に F9，F5（引数は `empty.txt`）。1 回目で止まり，**Locals** の `ch` は `-1`。`-1` は `EOF` の値であることを確かめさせる（文字ではない）。
3. `input.txt` に戻し，同じブレークポイントで F5（**Debug > Continue**）を繰り返す。20 回は `ch` が文字の文字コード（`a` の 97 など），21 回目だけ `-1` で止まる。`int` の `ch` は **Locals** に数だけで表示されるので，文字も見たいときは **Debug > Windows > Watch > Watch 1**（授業では未習。第13回の演習で使う）に `(char)ch` と書く（`97 'a'` のように表示される）。最後の回は `-1 'ÿ'` のように文字が付いて見えるが，これは文字ではなく `EOF` の値 −1 である。
4. **仮説**: 「`feof` は読み取りに失敗した**後**で真になる。最後の文字を読んだ時点ではまだ偽なので，もう 1 回ループに入り，`fgetc` が `EOF` を返した回も数えている」。
5. **確かめる**: 20 回目（`ch` が 10，改行 `'\n'` の文字コード。最後の文字）で止まったら，F10 で 1 文ずつ進める。`while (!feof(fp))` の条件の後でもう一度本体に入り，`int ch = fgetc(fp);` の後の `ch` が `-1` になって `++chars` を通ることを見る。
   最後の文字を読んだ時点では `feof` がまだ偽であることを，講義 3 節の説明（「`feof`は『次に読めるかの予報』ではなく，既に行った読み取りで終端に達したかを調べるもの」）と照らし合わせる。

## ヒントの段階

1. 「空のファイルで試そう。ループの本体は何回実行された？」
2. 「最後の 1 回の繰り返しで止まったとき，`ch` はいくつ？ それは文字？」
3. 「`feof(fp)` が真になるのは，最後の文字を読んだとき？ それとも読もうとして失敗したとき？」

## 原因

`feof` は「すでに行った読み取りがファイルの終わりに達したか」を表す。最後の文字を読んだ時点ではまだ偽なので，ループにもう 1 回入り，`fgetc` が `EOF`（−1）を返した回まで `++chars` する。空のファイルでも 1 回入る。
行数が正しいのは，`EOF` が `'\n'` と等しくないからで，たまたま。講義 3 節のとおり，終了は読み取り関数の戻り値で決める（講義 1 節「`while (!feof(fp))` で先に終了を予測するのではなく…」）。

## 直し方

```diff
-    while (!feof(fp)) {
-        int ch = fgetc(fp);
+    int ch;
+    while ((ch = fgetc(fp)) != EOF) {
         ++chars;
```

直した版は `input.txt` で `chars=20 lines=3`，空のファイルで `chars=0 lines=0`，最後に改行のないファイル（`apple`⏎`banana`）で `chars=12 lines=1` を表示する（テスト `variant_fixed--*`）。

## 学生への問い

- 問「`ch` を表示する（`putchar(ch)`）プログラムだったら，誤りの版はどう見えた？」→ 最後に `EOF` を `putchar` するので，意味のない 1 バイト（0xFF）が余分に出る。
- 問「`fgets` で 1 行ずつ読むときも同じ誤りが起きる？」→ 起きる。`while (!feof(fp))` の中で `fgets` の戻り値を調べないと，最後に失敗した回で前の行をもう一度処理する（講義 3 節「最後に失敗した値を処理してしまう」）。
- 問「このプログラムのテストに，どのファイルを用意する？」→ 空のファイル，1 文字だけのファイル，最後に改行のないファイル，普通の複数行。
