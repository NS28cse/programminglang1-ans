# BugReverseWord　単語を逆順に表示する（第7回）

ソース: [reverse_word.c](reverse_word.c)

> [!IMPORTANT]
> この題材の誤りは**未定義動作**（配列の外への書き込み）で，症状は環境・構成で変わる。下の MSVC の症状は，Debug 構成の実行時チェック（`/RTC1`）の仕様から通常見られるもの（授業の前に TA が手元で一度確かめる）。Linux の症状は GCC で実際に実行したもの。
> 学生に「表示が正しいので問題ない」と結論させないことが，この題材のねらいの 1 つ。

## 対象の回と前提

- 第7回（入出力）。講義 3 節「容量の直前・ちょうど・超過を区別する」と，課題3 `LineInput`（行の容量）の後。第6回の「終端を持つ `char` 配列」「容量を確かめて連結する」の続き。
- 学生が知っていること: `getchar` と `EOF`，`char` 配列の文字列と終端 `'\0'`，`enum` の定数，ブレークポイント（F9）・F5・F10・**Locals**。
- 標準入力を使う（引数・ファイルはない）。

## プログラムがするはずのこと

標準入力の 1 行目のうち先頭の `MAX_WORD`（8）文字までを配列 `word` に文字列として入れ（9 文字目以降は捨てる），その文字列と逆順の文字列を表示する。`stack` なら:

```text
word: stack
reversed: kcats
```

## 症状

**Startup Item** で `debugging BugReverseWord` を選び，Ctrl+F5 で実行して，1 行入力して Enter を押す。

- 7 文字以下（`stack` など）: 期待どおりに表示して終わる。
- 8 文字ちょうど（`abcdefgh`）以上: Debug 構成の MSVC では，`word: abcdefgh` と `reversed: hgfedcba` が**正しく表示された後**，`main` から戻るときに **Run-Time Check Failure #2 - Stack around the variable 'word' was corrupted.** というダイアログが出る（Debug 構成の既定の設定。Ctrl+F5 では **Microsoft Visual C++ Runtime Library** の **Debug Error!** のダイアログ）。
  Release 構成ではこの検査がないので，何も起きないように見えることが多い。
- Linux の GCC（Debug，サニタイザーなし）では，8 文字でも 11 文字でも表示は正しく，異常終了もしない:

  ```text
  word: abcdefgh
  reversed: hgfedcba
  ```

- AddressSanitizer 付き（`-DSOFTPRAC_SANITIZE=ON`）では，`'\0'` を書く行で止まる:

  ```text
  .../reverse_word.c:24:9: runtime error: index 8 out of bounds for type 'char [8]'
  ==...==ERROR: AddressSanitizer: stack-buffer-overflow on address ... 
  WRITE of size 1 at ... thread T0
      #0 ... in main .../reverse_word.c:24
  ```

未定義動作なので，バグ入りの版は自動テストで実行しない（直した版だけをテストする）。

## 学生への渡し方

- 渡すもの: `reverse_word.c` だけ。Debug 構成で実行するように言う。
- 最初に言うこと: 「8 文字までの単語を逆順に表示するプログラムです。Debug 構成で Ctrl+F5 で実行し，`abcdefgh` と入力して Enter を押すと，`word: abcdefgh` と `reversed: hgfedcba` が出て正常に終わるはずですが，表示の後でエラーのダイアログが出ます（`stack` では出ません）。原因をデバッガで探してください」
- 言わないこと: 終端の分の要素，`word[8]`。

## 探し方

1. **ダイアログを読む**: 「`word` という変数のまわりのスタックが壊れた」と言っている。止まったのは `main` の終わりだが，壊したのはその前のどこか（**Run-Time Check** は関数から戻るときに調べる）。範囲は「`word` に書き込む行」に絞れる。書き込む行は 2 つ（`word[length] = (char)ch;` と `word[length] = '\0';`）。
2. **境界の入力で比べる**: 7 文字（`abcdefg`）ではダイアログが出ず，8 文字で出る。「8 文字のときだけ，どこかの添字が範囲を超える」と仮説の見当を付ける。
3. **止めて値を見る**: `word[length] = '\0';` の行に F9，F5 で `abcdefgh` を入力。**Locals** で `length` が 8 であること，`word` を展開すると `[0]`〜`[7]` の 8 要素しかないことを見る。
4. **仮説**: 「8 文字入れると `length` が 8 になり，`word[8]`（9 番目の要素）に `'\0'` を書いている。`word` は 8 要素なので，その外を壊している」。
5. **確かめる**: 「8 文字の文字列を入れるには何要素必要？」と聞く（終端を含めて 9）。余裕があれば **Debug > Windows > Memory > Memory 1**（授業では未習）の **Address** に `word` と入れ，F10 で `'\0'` を書く前後に，8 バイトの文字の直後の 1 バイトが 00 に変わることを見せる。

## ヒントの段階

1. 「ダイアログの文面を読もう。どの変数が壊れたと言っている？ 7 文字と 8 文字で比べると？」
2. 「8 文字入れたとき，`'\0'` を書く行の `length` はいくつ？ `word` の添字は何番まで？」
3. 「8 文字の文字列を入れるのに，`char` は何個必要？」

## 原因

仕様は「8 文字まで」で，文字を入れる判定 `length < MAX_WORD` は正しい。しかし文字列として使うには終端 `'\0'` の 1 要素が要るのに，配列を `char word[MAX_WORD]`（8 要素）で宣言している。8 文字入れると `length` が 8 になり，`word[length] = '\0';` が `word[8]`（配列の外）へ書き込む。
範囲外の書き込みは未定義動作で，すぐ隣のメモリがたまたま使われていなければ表示は正しく見える（第5回 講義 1 節「範囲外のアクセスは実行して確かめない」，第6回 講義 1 節「終端を持つ`char`配列」）。
添字 `length` は入力で決まるので，コンパイラの警告では見つからない。

## 直し方

```diff
-    char word[MAX_WORD];
+    char word[MAX_WORD + 1];
```

最大の文字数と終端の 1 要素を分けて書く。直した版は 1 文字・5 文字・8 文字ちょうど・10 文字（8 文字に切り詰め）・空行を確かめている（テスト `variant_fixed--*`）。

## 学生への問い

- 問「Linux や Release 構成では何も起きなかった。それでも直す必要がある？」→ ある。配列の外への書き込みは未定義動作で，表示が正しいのはたまたま。別の変数（`length` など）が隣にあれば，その値を壊すこともある。
- 問「入力の判定を `length < MAX_WORD - 1` にして 7 文字までにする直し方は？」→ 範囲外の書き込みはなくなるが，「8 文字まで」の仕様を満たさない。仕様を変えずに容量を 1 増やす。
- 問「この誤りを見つけるには，どの長さの入力を試す？」→ 容量ちょうど（8 文字）と，それを超える長さ（9 文字以上）。容量の直前（7 文字）では見つからない。
