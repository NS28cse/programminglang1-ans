# BugEvenSum　偶数の合計（第4回）

ソース: [even_sum.c](even_sum.c)

## 対象の回と前提

- 第4回（制御構造）。課題2 `EvenSum` と同じ処理なので，課題2を終えた学生や，講義 7 節で初めてデバッガを使う場面に向く。
- 学生が知っていること: `for`・`if`・`%`，ブレークポイント（F9），デバッグ実行（F5），ステップオーバー（F10），ローカル変数の表示（**Locals**）。
- 入力も引数もない（`n` は `main` の中の固定値）。

## プログラムがするはずのこと

1 から `n` までの整数のうち偶数だけを足し，`sum=合計` と表示する。`n = 10` なら 2 + 4 + 6 + 8 + 10 = 30 で，`sum=30` と表示されるはず。

## 症状

**Startup Item** で `debugging BugEvenSum` を選び，Ctrl+F5（**Debug > Start Without Debugging**）で実行する。

```text
sum=20
```

期待は `sum=30`。Windows（MSVC）でも Linux（GCC・Clang）でも同じ表示になる（テスト `debugging/BugEvenSum/symptom`）。
`n` を 4 に書き換えると `sum=2`（期待は 6），9 に書き換えると `sum=20`（期待も 20 で一致する）。

## 学生への渡し方

- 渡すもの: `even_sum.c` だけ。
- 最初に言うこと: 「1 から n までの偶数の合計を表示するプログラムです。n = 10 なら 30 のはずですが，20 と出ます。どこで期待とずれるかを，デバッガで確かめてください。直すのは，原因を 1 文で説明できてからにしましょう」
- 言わないこと: `for` の条件・`<` と `<=` の話。差が 10 であることも，学生が自分で計算するまで待つ。

## 探し方

1. **症状を数で言う**: 期待 30 と実際 20 の差は 10。「足されていない数があるとしたら，どれか」を考えさせる（10 そのもの）。
2. **範囲を絞る（入力を小さくする）**: `n` を 4 にして再現させる（期待 6，実際 2）。止める回数が少なくなる。
3. **流れを見る**: `sum += i;` の行で F9（**Debug > Toggle Breakpoint**）→ F5（**Debug > Start Debugging**）。止まるたびに **Debug > Windows > Locals** で `i` と `sum` を確かめ，F5（**Debug > Continue**）で次へ進む。止まるのは `i` が 2 のときだけで，4 では止まらずに表示まで進む。
4. **仮説**: 「`i` が `n` と等しいときに本体が実行されていない。`for` の条件が `i` = `n` で偽になっているのでは」。
5. **確かめる**: ブレークポイントを `for` の行へ移し，F10（**Debug > Step Over**）で進める。**Locals** の `i` が 4 になった直後の F10 で，本体ではなく `printf` の行へ移ることを見る。条件 `i < n` に `i = 4`，`n = 4` を当てはめて偽になることを，学生に声に出して言わせる。
6. 確かめ終わったら Shift+F5（**Debug > Stop Debugging**）で止め，`n` を 10 に戻してから直す。

## ヒントの段階

1. 「`n` を 4 にすると，期待はいくつ？ 実際はいくつ？」
2. 「`sum += i;` で止まったときの `i` を全部書き出してみよう。4 で止まった？」
3. 「`i` が `n` と同じ値のとき，`for` の条件は真？ 偽？」

## 原因

`for (int i = 1; i < n; ++i)` は `i` = 1〜`n` − 1 を調べる。「1 から n まで」（両端を含む）なら条件は `i <= n`。
`n` が偶数のときだけ最後の偶数 `n` が抜けるので，`n` = 9 のような奇数で試しても気付けない（講義 3 節「`N`回の反復とカウンタの範囲」，講義 7 節の表「端の値だけ結果が違う」）。

## 直し方

```diff
-    for (int i = 1; i < n; ++i) {
+    for (int i = 1; i <= n; ++i) {
```

直した版は `sum=30` を表示する（テスト `variant_fixed`）。

## 学生への問い

- 問「`n = 9` だけで試していたら，この誤りに気付けた？」→ 気付けない。9 は奇数なので，抜けた `i = 9` は足されない数で，結果が同じになる。
- 問「この誤りを必ず捕まえる，いちばん小さい `n` は？」→ 2（期待 2，誤りの版では 0）。境界の `n` が偶数になる値を選ぶ。
- 問「`for (int i = 0; i < n; ++i)` なら `<` で正しいのはなぜ？」→ 0 から始めると `n` 回で `n` − 1 まで進むから。始まりの値と条件を組で考える。
